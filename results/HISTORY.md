# How the evaluation changed the code

The current results (`test_results.md`, `sample_outputs/`) come from the final run with the final code. Four
earlier runs are kept because each one exposed a problem that the automatic checks either missed or only caught
later.

| Run | Folder | What it exposed | Fix |
|---|---|---|---|
| 1 | `run1_before_fixes/` | **Quota.** `gemini-3.5-flash` allows 20 free requests/day. From S3 on, every call failed with HTTP 429 before the fallback model answered, so latency doubled and model-call counts were inflated (see the `models` field). **Latent wrong place (S9).** With weather offline, the agent retried "Goa" as "Panaji". The geocoder has no such town and ranked "Panāji Muwara", a village in Gujarat, first. The outage hid that weather would have been fetched for the wrong place. | `ModelSelector`: skip a model for 10 min after a quota error, shared by all conversations; failed calls counted separately. Geocoder: only exact names, or fuzzy matches of towns with at least 15,000 people; ignore airports and parks; otherwise `place_not_found` with the closest names. |
| 2 | `run2_before_budget_fix/` | All 10 scenarios passed, but reading the transcripts showed that **3-day plans were budgeted for 3 nights** (S1, S6) and that S6 **assumed 2 travellers** the user never mentioned. New checks (`budget uses N nights and M travellers`), re-applied with `--rescore`, turn S1 and S6 red. | `estimate_trip_budget` derives nights from start/end dates and notes a mismatch; the prompt says an unstated group size means 1 traveller, stated as an assumption. |
| 3 | `run3_ambiguous_place_failure/` | S6 re-run: this time the model did **not** notice that "Manali" resolved to Tamil Nadu. It presented 27 °C Chennai-suburb weather as "crisp mountain conditions". Every number was traced to a tool, so the answer was 100 % numerically grounded, and wrong. Runs 1 and 2 had self-corrected, so the prompt-only rule was not reliable. | `get_weather` refuses same-name towns when the second is at least 1/10 the size of the first (`ambiguous_place` + options), so the model must choose a qualified name. S6 then passed. |
| 4 | `run4_invented_weather/` | **Invented weather (S6).** `get_weather` correctly refused "Manali" as ambiguous, but the model never retried. Its answer gave "highs around 10°C to 14°C … Source: Open-Meteo historical proxy", figures that no tool returned, attributed to a tool that had failed. The JSON plan repeated them as `historical_proxy`. **Transient outage (S2, S7).** The fallback model returned `503 UNAVAILABLE` ("high demand") and the turns crashed. | `GroundingGuardMiddleware`: after every final answer, temperature and rainfall figures must match a tool result. If they don't, the model is sent back once with a correction request, and a visible warning is added if it insists. The evaluation's grounding metric thus became a runtime guardrail. `ModelSelector` retries transient 5xx errors after 5 s and 20 s. |
